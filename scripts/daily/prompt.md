## 2. Выбор тем

Напиши порцию примерно из **10 статей**.

- Список ненаписанных тем: запусти `scripts/topics.py` и смотри
  `_generated/topics.json` (у написанных тем есть поле `href`).
- Порядок: сначала закрываем весь текущий курс (сейчас 2-й), потом
  следующий. Внутри курса тема берётся, только если все её `requires`
  уже написаны. Предпочитай цепочки (тема и её прямые продолжения) и
  чередуй математику с физикой, чтобы физические разделы не отставали.
- Если для темы нужен новый раздел, создай его `index.qmd` по образцу
  существующих (`math/algebra/index.qmd`).
- Если карта тем (`topics.yml`) кажется неправильной (не хватает
  зависимости, тема не на том курсе), не меняй её молча: запиши
  предложение в журнал как вопрос.

## 3. Как писать статью

Образец стиля — уже опубликованные статьи (например,
`math/algebra/metric.qmd`, `physics/relativity/lorentz-transformations.qmd`).
Перед первой статьёй порции прочитай целиком хотя бы две из них.

Структура: мотивация из физики → определения (`::: {#def-...}`) →
вычисления и проверки в коде → физика → «Итоги» → 5 упражнений с
ответами в свёрнутом блоке `callout-tip`. Заголовок файла: `title`,
`topic`, `order`, `description` (без `level` и `requires` — они в карте).
Ссылки на другие статьи — относительные пути `.qmd` от корня (`/math/...`).
Ссылайся только на темы, которые есть в `topics.yml`, и называй их
точно так, как там.

Обязательные правила (каждое выстрадано на прошлых статьях):

- **Конвенции.** Все знаки и обозначения — строго по `conventions.qmd`.
  Если статье нужна новая конвенция, сначала добавь её в
  `conventions.qmd` и тест в `tests/test_conventions.py`, и обязательно
  упомяни это в отчёте отдельным пунктом.
- **Каждая формула проверена кодом.** Тождество — через
  `simplify(разность) == 0`; если `simplify` не справляется — `rewrite`,
  `fu`, численная подстановка.
- **Каждый ответ упражнения и каждое число в тексте пересчитай кодом**
  до коммита. Текст должен совпадать с реальным выводом ячеек.
- **Числа SymPy в f-строках** (`:+d`, `:.3f`) оборачивай в `int()`/`float()`.
- **Каждый рисунок посмотри** (Read PNG из `_site/.../figure-html/`):
  наложения подписей, пустые заливки, вводящие в заблуждение масштабы.
  Подпись рисунка должна соответствовать данным.
- Код читаем: короткие функции, комментарии по делу, как в соседних
  статьях. Общие инструменты, нужные нескольким статьям, — в пакет
  `src/gmph` с тестами в `tests/`.

Проверка перед коммитом каждой статьи:

```
conda run --no-capture-output -n gmph python -m pytest -q
conda run --no-capture-output -n gmph quarto render
```

Обе команды без ошибок; выводы ячеек статьи просмотрены (извлеки текст
`cell-output` из HTML в `_site`), блок «Уровень и связи» на месте.

Коммит — по одной статье, сообщение по образцу `git log`
(«Статья «…»» + краткое содержание), подпись автора берётся из
локального git-конфига, в конце строка
`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
После каждого коммита — `git push origin main`, чтобы готовые статьи
публиковались, даже если работа прервётся.
